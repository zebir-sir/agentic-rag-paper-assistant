# 46 篇 RRT 论文库评测说明

评测时间：以 `evals/results/corpus_46/corpus_readiness_eval.json` 的运行时间为准。评测对象为已完成入库的 46 篇 RRT 及相关路径规划论文；评测过程只读取现有索引，不重新入库、不修改论文数据。

## 1. 评测目标

本评测验证论文库是否已经成为可用的研究证据库，覆盖三个层面：

1. 入库结构是否完整，后续能否按章节、行号和图表/算法证据回溯。
2. 已知论文能否被混合检索稳定定位。
3. 每篇论文是否进入知识图谱，并形成可用于候选扩展的关系网络。

它不是开放式问答正确率 benchmark。开放式问答还需要人工构造问题、相关论文、支撑片段和答案质量标注，不能用 Hit@K 冒充答案正确率。

## 3. 检索口径

对 46 篇论文逐篇以其已入库标题作为 query，调用混合检索，检查返回结果中是否包含该论文的持久化 document ID。每条 case 都保存了目标 ID、返回 ID、排名与时延，详见 `evals/results/corpus_46/corpus_readiness_eval.json`。

这种口径评估的是“研究者已知某篇文献时，系统能否在当前论文库中定位到它”，适合证明索引、向量化与混合检索链路有效。

## 4. 失败分析与改进

Hit@5 未命中的 3 篇均不是检索服务错误，而是文献标题质量问题：原始 PDF 首屏或元数据被解析为会议录标题、期刊名，或标题字符不规范，导致 query 不能表达真实论文主题。

下一轮改进将采用标题规范化优先级：PDF 解析标题 -> 文件名规则 -> LLM 校正（只在低置信度时） -> 用户可编辑确认。该策略会同时改善资料库标题、星图节点缩写和标题检索。

## 5. 秋招表述

> 我构建了一个面向 RRT 与运动规划的个人研究论文库，46 篇论文经过 Docling 结构化解析后形成 5,467 个可追溯片段，章节与行号元数据覆盖率均为 100%，同时单独保留了 1,204 条图、表和算法证据。每篇论文会物化为知识图谱节点，当前形成 430 条语义相似、引用和方法谱系关系。对于已知论文定位，我对 46 篇论文逐篇进行了全量混合检索评测，Hit@1 为 91.3%，Hit@5 为 93.5%，P50 检索时延约 0.73 秒。这个指标只用于说明检索定位能力，开放式问答正确性仍通过证据引用和后续人工标注集单独评估。

## 6. 复现

先确保 API 正在运行。容器内执行时使用容器端口：

```powershell
docker compose exec -T api python evals/run_ingestion_quality_eval.py --output-dir evals/results/corpus_46
docker compose exec -T api python evals/run_corpus_readiness_eval.py --api-url http://localhost:8888 --output-dir evals/results/corpus_46
```

宿主机直接执行脚本时使用 `http://localhost:8059`。
